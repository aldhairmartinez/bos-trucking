# Swapping in the Owner's Original Photos

**The current images are temporary.** All twelve supplied files are 1290×2796 iPhone
screenshots whose real content is a band in the middle. Replacing them requires **no
redesign** and touches **one file**.

---

## Why it is one file

The HTML never references a camera filename. It references stable logical IDs defined in
[`assets/sources.json`](../assets/sources.json):

```
assets/sources.json          "bos-mack-dump-truck"
        ↓
public/img/trucks/bos-mack-dump-truck-{480,640,960,1280}.{avif,webp,jpg}
        ↓
index.html                   srcset="/img/trucks/bos-mack-dump-truck-960.avif …"
```

Change the source file behind the ID and every reference still resolves. The pipeline
regenerates the whole ladder.

---

## The procedure

### 1. Put the new files somewhere safe

```bash
mkdir -p assets/incoming
cp ~/Downloads/mack-granite-tri-axle.jpg assets/incoming/
```

`assets/incoming/` is committed alongside `assets/originals/`. **Never overwrite anything
in `assets/originals/`** — that directory is the owner's supplied files, byte-for-byte, and
`crop-source.py` only ever reads from it.

### 2. Edit the entry in `assets/sources.json`

```jsonc
"bos-mack-dump-truck": {
  "file": "incoming/mack-granite-tri-axle.jpg",  // 1. was originals/IMG_0653.PNG
  "group": "trucks",
  "crop": null,                                  // 2. a real original has no bars
  "focus": [0.44, 0.52],                         // 3. nudge if the subject moved
  "usage": "Material delivery feature, service card, gallery"
}
```

Three changes:

| Field | What to do |
|---|---|
| `file` | Point at the new file, relative to `assets/` |
| `crop` | **Set to `null`.** A real original has no letterbox bars and no flyer overlay to strip. Only set a box if you genuinely want to reframe |
| `focus` | `[x, y]` as fractions, `0..1`, of the cropped image. Where the subject is. `[0.5, 0.5]` is centre |

### 3. Rebuild and look

```bash
npm run images      # regenerate public/img/** and public/css/image-focus.css
npm run check       # confirm nothing broke
npm start           # review at http://localhost:8080
```

That is the whole process. No HTML edit, no CSS edit, no redesign.

## What improves automatically

The pipeline **never upscales** — output width is capped at the source's real width. With
today's screenshots the ladder stops at **1280**.

The markup already requests **1600 / 1920 / 2560** in every `srcset`. Those rungs appear
on their own as soon as a larger source exists. `build-images.py` prints which images are
still capped:

```
NOTE: these are capped by today's screenshot sources and will gain
      1600/1920/2560 rungs automatically once real originals are
      dropped into assets/sources.json:
        bos-lot-sunset-fort-myers
        bos-mack-dump-truck
        ...
```

When that list empties, every image is at full resolution.

## Tuning the framing

Photos are served at their **natural cropped aspect ratio**. Containers set
`aspect-ratio` and crop with `object-fit: cover`. The focal point decides what survives
that crop, travelling from `sources.json` into the generated
`public/css/image-focus.css`:

```css
/* GENERATED by scripts/build-images.py -- do not edit. */
.img-bos-mack-dump-truck { object-position: 44% 52%; }
```

So if a subject is cropped out of a card, **edit `focus` in the manifest and rerun** — do
not hand-edit CSS. That file is overwritten on every build.

Rough guide:

| Subject sits… | `focus` |
|---|---|
| Centre | `[0.5, 0.5]` |
| Left third | `[0.33, 0.5]` |
| Upper area (sky, signage) | `[0.5, 0.35]` |
| Lower area (ground, wheels) | `[0.5, 0.65]` |

The hero is the one exception: it is art-directed across **two different photographs**
(sunset panorama on desktop, dump truck in portrait on phones), so its framing lives in
`layout.css` per breakpoint rather than in the manifest.

## What to ask the owner for

| Want | Why |
|---|---|
| **Original camera files** for the sunset lot, the Mack dump truck, the yard sign and the gate | The single biggest quality upgrade available. Phone screenshots cap us at ~1290px |
| **Logo as SVG / AI / EPS** | Currently raster-only. A vector logo renders perfectly at every size and makes the black-keying step unnecessary |
| A clean version of the **sunset panorama without marketing overlays** | We cropped the overlays off, which cost most of the frame's height. The untouched original would give a far better hero |
| A **daytime photo of the truck** | The only equipment photo is a night shot. A daylight shot would strengthen both the service card and the gallery |
| Any **newer photos** — loaded trucks, material piles, trailers in the lot | More real photography means less reliance on the same five frames |

Ask for AirDrop or an iCloud/Google Drive link, and specifically **not** screenshots —
that is how we ended up here.

## Adding a brand-new image

1. Drop the file in `assets/incoming/`
2. Add an entry to `assets/sources.json` with a descriptive, SEO-friendly ID
   (`bos-loaded-dump-truck`, not `img4`), a `group`, `crop`, `focus` and `usage`
3. `npm run images`
4. Reference it in the HTML with a `<picture>` modelled on an existing one, and add
   `class="img-<your-id>"` to the `<img>` so the generated focal-point rule applies
5. If it lives in a **new** `object-fit` container, add that container's selector to the
   `<picture>` stretch rule in `public/css/base.css` — there is a comment there explaining
   why
6. `npm run check`

## Verifying the originals were never touched

```bash
# Byte-identical to what the owner supplied
cmp assets/originals/IMG_0653.PNG /path/to/owner-copy/IMG_0653.PNG

# Nothing in the pipeline writes to originals/
grep -rn "originals" scripts/        # read paths only
```

`crop-source.py` opens files in `assets/originals/` and writes only to `assets/masters/`,
`assets/brand/` and `assets/reference/`. `build-images.py` reads those and writes only to
`public/img/`.
